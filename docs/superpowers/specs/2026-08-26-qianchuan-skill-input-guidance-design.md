# 千川技能输入引导设计

## 目标

将千川元技能的入口元数据和正文改为与云图技能一致的紧凑结构，使客户能按固定顺序提供查询范围、指标筛选和高光帧规则；结构化 `QuerySpec` 仍只写 API 原始字段名。

## 范围

修改根目录 `SKILL.md` 的 YAML frontmatter 和说明结构。不修改查询脚本、RPA 协议、字段注册表或既有 `QuerySpec` / `HighlightSpec` schema。

## 输入引导

新增 `argument_hint` 和 `metadata.pre_input`。客户输入按以下三个独立组出现，且顺序固定：

1. 查询范围：授权店铺 ID、广告主 ID、日期范围。
2. 指标筛选：可选阈值条件、排序指标、升序或降序、目标 Top N。仅举中文例子：综合消耗、净成交金额、净成交 ROI、净成交订单成本、视频完播率。
3. 高光帧规则：是否保留第 0 秒帧，以及点击、流失、点赞、评论、分享、新增粉丝的选帧策略和帧数。

不在入口引导中出现素材类型或候选池大小。`candidateTopN` 仍是内部候选补位控制参数，不作为客户输入。

## 字段契约

客户可使用中文业务名表达意图；解析时查询 `config/asset-field-registry-v1.json`，把它转换为 QuerySpec 中的 API 原始字段名。固定报表契约的 102 个指标均可作为 `metricFilters` 和 `ranking.field`，但 `pre_input` 不列出全量技术字段。API 百分比保留百分点单位。

## 技能正文

正文采用云图技能的简洁分段：概述、`## 输入`、`## 执行`、`## 产物与恢复`。保留千川专属约束：双 ID 域隔离、单条素材汇总结果直读、非 AIGC 重复素材 ID 拒绝、显式 `--execute-rpa`、排名顺序失败补位、临时视频和高光帧处理、离线 `verify-run`。

## 验收

1. YAML frontmatter 包含 `argument_hint` 和 `metadata.pre_input`。
2. `pre_input` 的三个输入组顺序为查询范围、指标筛选、高光帧规则。
3. 指标筛选包含排序方向和目标 Top N，不包含素材类型与候选池大小。
4. 正文说明中文指标到 API 原始字段名的转换，并保留 102 指标可筛选、可排序的契约。
5. `SKILL.md` 继续可被仓库的技能校验命令读取。
